# Native Android App (Play Store Internal Testing) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Wrap the existing `frontend/` PWA in a Capacitor Android shell and
stand up a manual-trigger GitHub Actions pipeline that builds, signs, and
uploads it to the Play Console internal testing track.

**Architecture:** `frontend/android/` (Capacitor-generated Gradle project)
bundles `frontend/dist` and calls the same production API the PWA and iOS app
already use. No backend changes. Signing uses Play App Signing — CI only
needs a locally-generated upload keystore, no certificate-storage repo like
iOS's `ios-certs`. A new `.github/workflows/deploy-android.yml` runs Fastlane
on `ubuntu-latest` on manual dispatch only.

**Tech Stack:** Capacitor 6, `@capacitor/camera` (already installed), Fastlane
(`gradle` + `upload_to_play_store`), GitHub Actions (`ubuntu-latest`).

## Global Constraints

- Backend, the web deploy pipeline (`.github/workflows/deploy.yml`), and the
  iOS pipeline (`.github/workflows/deploy-ios.yml`) are untouched — see
  `docs/specs/2026-08-08-android-app-design.md`.
- Package name (Android's `applicationId`) is `org.nammaindies.app` — same
  value as the iOS bundle ID, already set in `frontend/capacitor.config.ts`'s
  `appId`, carries over unchanged.
- Release track is **internal testing only**. No store listing, Data Safety
  form, or content rating work in this plan — parked per the design doc.
- Repo secrets `PLAY_SERVICE_ACCOUNT_JSON`, `ANDROID_KEYSTORE_BASE64`,
  `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD` do
  not exist yet — they're set during the Task 2/3 handoff to Akash, same
  shape as iOS's `match appstore` handoff.
- `frontend/src/` stays shared between the PWA, iOS app, and Android app — no
  forked copies of screens or components. `@capacitor/camera` and
  `takePhotoIfNative()` (`frontend/src/capture/takePhoto.ts`) already branch
  on `Capacitor.isNativePlatform()`, not per-OS — no new capture code needed.
- This is a packaging layer, not new app logic — no new automated tests
  expected (matches the iOS plan's precedent). Verification is manual: Gradle
  build succeeds, app installs and runs.

- [ ] **Step 1: Create the Fastlane directory and Gemfile**

```bash
mkdir -p frontend/android/fastlane

source "https://rubygems.org"
gem "fastlane"
EOF
```

- [ ] **Step 2: Write the Appfile**

`frontend/android/fastlane/Appfile`:
```ruby
json_key_data(ENV["PLAY_SERVICE_ACCOUNT_JSON"])
package_name("org.nammaindies.app")
```

- [ ] **Step 3: Write the Fastfile**

`frontend/android/fastlane/Fastfile`:
```ruby
default_platform(:android)

platform :android do
  desc "Build a signed release AAB"
  lane :build do
    gradle(
      task: "bundle",
      build_type: "Release",
      properties: {
        "android.injected.signing.store.file" => ENV["ANDROID_KEYSTORE_PATH"],
        "android.injected.signing.store.password" => ENV["ANDROID_KEYSTORE_PASSWORD"],
        "android.injected.signing.key.alias" => ENV["ANDROID_KEY_ALIAS"],
        "android.injected.signing.key.password" => ENV["ANDROID_KEY_PASSWORD"],
      },
    )
  end

  desc "Build and upload a release build to the Play Console internal testing track"
  lane :build_and_upload do
    build
    upload_to_play_store(
      track: "internal",
      aab: "app/build/outputs/bundle/release/app-release.aab",
      skip_upload_metadata: true,
      skip_upload_images: true,
      skip_upload_screenshots: true,
    )
  end
end
```

`upload_to_play_store`'s Play Console auth comes from the Appfile's
`json_key_data(ENV["PLAY_SERVICE_ACCOUNT_JSON"])` — that's why
`PLAY_SERVICE_ACCOUNT_JSON` is stored as plain JSON text, not base64, when set
as a GitHub secret (mirrors how iOS's `ASC_API_KEY` takes raw `.p8` PEM text
directly). The `skip_upload_*` flags matter because there's no store listing
yet — without them, `upload_to_play_store` tries to push metadata/images that
don't exist and fails.

`android.injected.signing.*` properties sign the release build without
needing a `signingConfig` block in `app/build.gradle` — this only works
because Capacitor's generated `app/build.gradle` doesn't already assign a
`signingConfig` to the `release` build type. Verify this is still true (check
`frontend/android/app/build.gradle`'s `buildTypes { release { ... } }` block
has no `signingConfig` line) before relying on it; if Capacitor's template
ever changes to add one, remove it so the injected properties take effect.

- [ ] **Step 5: Commit**

```bash
git add frontend/android/Gemfile frontend/android/fastlane frontend/.gitignore
git commit -m "ci: scaffold fastlane config for Android signing and Play upload"
```

**Handoff to Akash after this task:** three things, all interactive and
tied to your Google account:

1. Finish Play Console developer account verification (identity, device,
   phone) if not already done.
2. Create the app record in Play Console (package name
   `org.nammaindies.app`, name "Namma Indies"), and add yourself under
   Testing → Internal testing → Testers.
3. Generate the upload keystore locally (needs a JDK with `keytool`):
   ```bash
   keytool -genkeypair -v -keystore upload-keystore.jks -alias upload \
     -keyalg RSA -keysize 2048 -validity 9125
   ```
   Keep the resulting `upload-keystore.jks`, the keystore password, the key
   alias (`upload`), and the key password — Task 3 turns these into repo
   secrets. Do not commit this file; it's already gitignored by Step 4 above.
4. Create a service account for CI: Play Console → Setup → API access →
   create a new service account (this opens Google Cloud Console) → grant it
   the "Release manager" role for this app under Play Console's Users and
   permissions → generate and download its JSON key. This becomes
   `PLAY_SERVICE_ACCOUNT_JSON`.

### Task 3: GitHub Actions → Fastlane → Play Console internal testing track

**Files:**
- Create: `.github/workflows/deploy-android.yml`

**Interfaces:**
- Consumes: `PLAY_SERVICE_ACCOUNT_JSON`, `ANDROID_KEYSTORE_BASE64`,
  `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`
  (new repo secrets — set during Task 2's handoff).
- Produces: nothing consumed elsewhere — this is the pipeline's terminal
  step.

- [ ] **Step 1: Write the workflow**

`.github/workflows/deploy-android.yml`:
```yaml
name: Deploy Android (Play Console internal testing)

# Manual only — a Play Console upload is a deliberate release, not something
# that should fire on every merge like the web deploy does.
on:
  workflow_dispatch: {}

concurrency:
  group: android-play-deploy
  cancel-in-progress: false

jobs:
  build_and_upload:
    runs-on: ubuntu-latest
    defaults:
      run:
        working-directory: frontend
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4
        with:
          node-version: "20"

      - name: Install frontend deps and build web assets
        run: |
          npm ci
          npm run build

      - uses: actions/setup-java@v4
        with:
          distribution: "temurin"
          java-version: "17"

      - uses: ruby/setup-ruby@v1
        with:
          ruby-version: "3.3"
          bundler-cache: true
          working-directory: frontend/android

      - name: Sync web build into the Capacitor Android project
        run: npx cap sync android

      - name: Decode the upload keystore
        working-directory: frontend/android
        env:
          ANDROID_KEYSTORE_BASE64: ${{ secrets.ANDROID_KEYSTORE_BASE64 }}
        run: echo "$ANDROID_KEYSTORE_BASE64" | base64 --decode > app/upload-keystore.jks

      - name: Build and upload to the internal testing track
        working-directory: frontend/android
        env:
          ANDROID_KEYSTORE_PATH: app/upload-keystore.jks
          ANDROID_KEYSTORE_PASSWORD: ${{ secrets.ANDROID_KEYSTORE_PASSWORD }}
          ANDROID_KEY_ALIAS: ${{ secrets.ANDROID_KEY_ALIAS }}
          ANDROID_KEY_PASSWORD: ${{ secrets.ANDROID_KEY_PASSWORD }}
          PLAY_SERVICE_ACCOUNT_JSON: ${{ secrets.PLAY_SERVICE_ACCOUNT_JSON }}
        run: bundle exec fastlane build_and_upload
```

`ANDROID_KEYSTORE_BASE64` is the base64-encoded `upload-keystore.jks` file
(`base64 -i upload-keystore.jks | pbcopy` on macOS to get the value to paste
into the GitHub secret) — encoded because it's binary, unlike
`PLAY_SERVICE_ACCOUNT_JSON` which is already text.

```markdown
## Android app (Play Store internal testing)

Native wrapper of the same frontend, distributed via Play Console's internal
testing track — separate release cadence from the web deploy and the iOS app
above. See `docs/specs/2026-08-08-android-app-design.md` for the full design.

- **Ship a new build:** GitHub → Actions → "Deploy Android (Play Console
  internal testing)" → Run workflow. Manual only — unlike the web deploy,
  this does not fire on merge to `main`. Testers get the update via the Play
  Store app, usually within a few minutes.
- **Add a tester:** Play Console → Testing → Internal testing → Testers →
  add by email (they need to accept the tester invite link once).
- **Signing** uses Play App Signing — Google holds the app-signing key. CI
  only holds the *upload* keystore, base64-encoded in the
  `ANDROID_KEYSTORE_BASE64` repo secret. Losing that keystore isn't fatal
  (unlike losing an iOS signing cert) — Play Console can reset the upload key
  via a support request, since Google still holds the real signing key.
- **Backend changes reach the native app automatically** — it calls the same
  production API as the PWA and iOS app. Only frontend UI changes need a new
  build.
- **Public listing not built yet.** Google requires a continuous closed test
  (12+ testers, 14 days) before production/public listing unlocks — internal
  testing is unaffected by that requirement and is what's wired up today.
```
