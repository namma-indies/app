# Native iOS App (TestFlight) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Wrap the existing `frontend/` PWA in a Capacitor iOS shell and stand up
a manual-trigger GitHub Actions pipeline that builds, signs, and uploads it to
TestFlight.

**Architecture:** `frontend/ios/` (Capacitor-generated Xcode project) bundles
`frontend/dist` and calls the same production API the PWA already uses. No
backend changes. Signing certs live encrypted in the `namma-indies/ios-certs`
private repo, managed by `fastlane match`. A new `.github/workflows/deploy-ios.yml`
runs Fastlane on `macos-latest` on manual dispatch only.

**Tech Stack:** Capacitor 6, `@capacitor/camera`, Fastlane (`match` + `pilot`),
GitHub Actions (`macos-latest`).

## Global Constraints

- Backend and the existing web deploy pipeline (`.github/workflows/deploy.yml`)
  are untouched — see `docs/specs/2026-08-05-ios-app-design.md`.
- Bundle ID is `org.nammaindies.app` (already registered in Apple's Certificates,
  Identifiers & Profiles and used to create the App Store Connect app record).
- Repo secrets `ASC_API_KEY`, `ASC_KEY_ID`, `ASC_ISSUER_ID` already exist on
  `namma-indies/app` (set manually, verified via `gh secret list`).
- Signing cert storage repo `namma-indies/ios-certs` already exists (private,
  empty, created via `gh repo create`).
- `frontend/src/` stays shared between the PWA and the native build — no
  forked copies of screens or components.
- Follow existing test conventions: Vitest, `@testing-library/react`, tests
  colocated as `*.test.tsx`/`*.test.ts` next to the file under test.

platform :ios do
  desc "Fetch/sync signing certs via match"
  lane :certs do
    app_store_connect_api_key(
      key_id: ENV["ASC_KEY_ID"],
      issuer_id: ENV["ASC_ISSUER_ID"],
      key_content: ENV["ASC_API_KEY"],
      is_key_content_base64: false,
    )
    match(type: "appstore", readonly: is_ci)
  end

  desc "Build and upload a release build to TestFlight"
  lane :build_and_upload do
    certs
    increment_build_number(xcodeproj: "App.xcodeproj")
    build_app(
      workspace: "App.xcworkspace",
      scheme: "App",
      export_method: "app-store",
    )
    upload_to_testflight(skip_waiting_for_build_processing: true)
  end
end

`app_store_connect_api_key`'s `key_content` takes the raw `.p8` text directly
(that's why `ASC_API_KEY` was stored as plain PEM text, not base64, when it
was set as a GitHub secret earlier).

- [ ] **Step 3: Write the implementation**

`frontend/src/capture/takePhoto.ts`:
```ts
import { Capacitor } from "@capacitor/core";

/**
 * Opens the native camera when running inside the Capacitor shell.
 * Returns null on web (caller falls back to the file-input flow) or if the
 * user cancels the capture.
 */
export async function takePhotoIfNative(): Promise<File | null> {
  if (!Capacitor.isNativePlatform()) return null;

  const { Camera, CameraResultType, CameraSource } = await import("@capacitor/camera");

  let webPath: string | undefined;
  let format = "jpeg";
  try {
    const photo = await Camera.getPhoto({
      quality: 85,
      resultType: CameraResultType.Uri,
      source: CameraSource.Camera,
      saveToGallery: true,
    });
    webPath = photo.webPath;
    format = photo.format || "jpeg";
  } catch {
    return null; // user cancelled
  }
  if (!webPath) return null;

  const blob = await fetch(webPath).then((r) => r.blob());
  return new File([blob], `sighting-${Date.now()}.${format}`, {
    type: blob.type || `image/${format}`,
  });
}
```

### Task 4: GitHub Actions → Fastlane → TestFlight

**Files:**
- Create: `.github/workflows/deploy-ios.yml`

**Interfaces:**
- Consumes: `ASC_API_KEY`, `ASC_KEY_ID`, `ASC_ISSUER_ID` (existing repo
  secrets), plus `MATCH_GIT_URL`/`MATCH_PASSWORD`/`ASC_TEAM_ID` (new — added
  once Task 1's handoff step runs `match appstore` for the first time and a
  team ID / match passphrase exist to record).
- Produces: nothing consumed elsewhere — this is the pipeline's terminal step.

- [ ] **Step 1: Write the workflow**

`.github/workflows/deploy-ios.yml`:
```yaml
name: Deploy iOS (TestFlight)

# Manual only — an App Store build is a deliberate release, not something
# that should fire on every merge like the web deploy does.
on:
  workflow_dispatch: {}

concurrency:
  group: ios-testflight-deploy
  cancel-in-progress: false

jobs:
  build_and_upload:
    runs-on: macos-latest
    defaults:
      run:
        working-directory: frontend
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4
        with:
          node-version: "20"

      - name: Install frontend deps and build web assets
        run: |
          npm ci
          npm run build

      - uses: ruby/setup-ruby@v1
        with:
          ruby-version: "3.3"
          bundler-cache: true
          working-directory: frontend/ios

      - name: Sync web build into the Capacitor iOS project
        run: npx cap sync ios

      - name: Build and upload to TestFlight
        working-directory: frontend/ios
        env:
          ASC_API_KEY: ${{ secrets.ASC_API_KEY }}
          ASC_KEY_ID: ${{ secrets.ASC_KEY_ID }}
          ASC_ISSUER_ID: ${{ secrets.ASC_ISSUER_ID }}
          ASC_TEAM_ID: ${{ secrets.ASC_TEAM_ID }}
          MATCH_PASSWORD: ${{ secrets.MATCH_PASSWORD }}
          MATCH_GIT_BASIC_AUTHORIZATION: ${{ secrets.MATCH_GIT_BASIC_AUTHORIZATION }}
        run: bundle exec fastlane build_and_upload
```

`MATCH_GIT_BASIC_AUTHORIZATION` is how `match` authenticates to the private
`ios-certs` repo over HTTPS in CI (a base64 `username:personal-access-token`
pair) — simpler than provisioning a deploy key for a repo that's read
constantly but written to rarely, from your own machine, not CI.

```bash

**Handoff to Akash after this task:** this is where the remaining secrets get

during the Task 1 handoff step — this task's workflow file is written first so
there's something for those secrets to plug into, but don't run the workflow
until they're set.

## iOS app (TestFlight)

Native wrapper of the same frontend, distributed via TestFlight — separate
release cadence from the web deploy above. See
`docs/specs/2026-08-05-ios-app-design.md` for the full design.

- **Ship a new build:** GitHub → Actions → "Deploy iOS (TestFlight)" →
  Run workflow. Manual only — unlike the web deploy, this does not fire on
  merge to `main`. Testers get a TestFlight notification automatically once
  the build finishes processing (10-30 min after upload).
- **Add a tester:** App Store Connect → TestFlight → internal or external
  testing group → add by email.
- **Signing certs** live encrypted in `namma-indies/ios-certs` (private),
  managed by `fastlane match`. Rotate the passphrase by re-running
  `fastlane match nuke appstore` then `fastlane match appstore` with a new
  `MATCH_PASSWORD`, updating the CI secret to match.
- **Backend changes reach the native app automatically** — it calls the same
  production API as the PWA. Only frontend UI changes need a new TestFlight
  build.
```
